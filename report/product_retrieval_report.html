The ask

  • Improve retrieval accuracy on structured retail product data where shoppers mix intent, brand, specs and exclusions.
  • Show which Databricks AI Search capabilities move the needle, with measured evidence rather than anecdotes.
  • Give a reproducible, governed evaluation harness the retailer can run on its own catalog.

How we measured

Data & index

  • retail_consumer_goods.product_search.products: 38,291 products, 500+ merchandise classes
  • Delta Sync AI Search index, managed databricks-gte-large-en embeddings, ANN / FULL_TEXT / HYBRID
  • MLflow evaluation dataset retail_consumer_goods.product_search.retrieval_eval: 600 queries, 6 types, ground truth from the catalog

Metrics (MLflow scorers)

  • hit@k, MRR@10, nDCG@10: is the right product found, and how high
  • constraint precision@10: share of results honoring brand / class / exclusion
  • excluded-brand leak: “not DeWalt” but DeWalt shown
  • latency (p50 / p90 / p99 from traces), LLM & ai_decide call counts
  • Correctness + retrieval judges on a 100-query subset

Why reranking alone moved the average less than expected

  1. Identifier lookups are invisible to relevance ranking. 100 of 600 queries are SKU/UPC lookups; every strategy that only ranks text scored at most MRR 0.00 on them, which caps the overall average.
  2. HYBRID leaves little headroom on the rest. Of 500 non-identifier queries the target is already at rank 1 for 350; only 129 have it at rank 2–10, the only slice a reranker can improve.
  3. Rerankers can only reorder. When the excluded brand fills the candidate pool, reranking cannot remove it; only a filter can.
  4. Coarse decisions tie. A 4-level score question leaves several candidates tied at the top, so order falls back to retrieval; continuous noul probabilities separate them.
  5. A cross-encoder is not instruction-following. It matches the words in the request, including the brand being excluded, and treats pack-size variants as equivalent.

How much of the remaining error is real?

Ground truth is the seed product a query was generated from. An ESCI-style LLM judge (Claude Sonnet 5.5) re-labels rank-1 results that aren't the seed: judged exact@1 counts the seed or a product judged an exact match. LLM judges are biased; treat as an estimate.

Recommendations

  1. Route by query shape first; it's the biggest, cheapest win. SKU/UPC → exact filter, "not X" → brand_name NOT filter parsed from the text (no LLM), else cleaned HYBRID. Fast router: MRR 0.845 on holdout at ~261 ms p50 vs HYBRID 0.645.
  2. Rerank the router's candidates with a GPU cross-encoder. Router + bge-reranker-v2-m3 (Model Serving, 25 candidates): MRR 0.930 dev / 0.919 holdout at ~596 ms p50, versus the ai_decide quality router 0.896 / 0.900 at ~1.2s. Qwen3-Reranker-0.6B was slower and no better on a small GPU.
  3. For the last points, learn the ranking. A LightGBM LambdaRank model over router candidates (pool/ANN/FULL_TEXT ranks, ai_decide, two cross-encoders, lexical features) reached MRR 0.939 (5-fold CV on dev) and 0.934 on holdout, the best result, but at ~3.6s p50 because every signal is computed per request; distil to the few strongest signals for production.
  4. Embed and enrich what shoppers search for. A compact title | brand | category | attributes | codes field helped every strategy (router 0.896 → 0.911); Doc2Query pseudo-queries added a little more (0.928) but are likely optimistic on this LLM-generated eval set. Qwen3 instruction-aware embeddings matched gte-large under the router (0.914).
  5. Keep LLMs out of the hot path unless they earn it. An LLM structured query plan scored 0.925 but leaked the excluded brand on 12% of exclusion queries vs 1% for the rules; LLM-planned filters varied run to run. Use them for the long tail the rules don't cover, with catalog validation and caching.
  6. Keep the rules as the router; add ai_decide only as a fallback. Classifying the route with one ai_decide call (create_router_tool(..., classifier="ai_decide")) tied the rules on holdout (0.920 vs 0.919 with bge) but missed some plain "not X" exclusions (brand leak 10% vs 1%) and added ~206 ms p50. On paraphrased exclusions the rules can't parse ("I'm done with DeWalt") it lifted MRR nan → nan. Run it only when the rules find no exclusion but the query names a catalog brand.
  7. Plan for scale: depth matters. On a ~5M-row storage-optimized index with near-duplicate distractors, the 12-candidate quality router fell to MRR 0.667 (hit@10 74%); 50 candidates: 0.713 with ai_decide, 0.783 with the bge cross-encoder. At 100M, budget deeper candidate pools and a fast cross-encoder.
  8. Measure honestly. An ESCI-style LLM judge found ~6 points of apparent rank-1 misses were valid alternatives (judged exact@1 92% for the enriched quality router), so true rank-1 accuracy is higher than hit@1 shows; confirm on real production query logs with graded labels before rollout. The MLflow dataset, scorers and traces make every change a measured experiment.
